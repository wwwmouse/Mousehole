# ROADMAP.md — mousehole 演进路线

**文档版本：** v0.2.0-mvp（Phase 5 交付后升 v0.3.0）  
**状态：** Phase 5 进行中  
**定位：** MVP 之后的阶段规划文档。一个阶段一个章节，只写清楚三件事：**要解决什么问题、用什么手段、最终结果如何**。技术细节见 `ARCHITECTURE.md`、`DATA_MODEL.md`、`UI_GUIDE.md`。

## 1. 北极星

mousehole 是面向个人用户的 **Local-first AI Workspace**：让资料、任务、执行和成果在同一个工作空间里持续积累，**越用越值钱**。

任何阶段都不破坏的三条底线：

1. **成果独立可追溯**：Artifact 不依附聊天，版本不覆盖历史。
2. **上下文显式受预算约束**：可用上下文 ≠ 实际输入。
3. **工具受控**：只允许 allowlist 内工具，无 Shell、无任意文件系统、无未经确认的外部写。

新功能只回答三个问题：是否强化“资料 → 任务 → 执行 → 成果 → 复用”的闭环？是否让结果更可核对、可复现？是否仍符合单用户、local-first、桌面优先？

## 3. Phase 5：v0.3.0「复用与可信」

### 3.1 要解决的问题

1. **复利断裂**：Artifact 只能看/下载/删除，不能编辑，也不能成为新 Task 的输入；成果没有全局入口。工作空间只“积累文件”，不“积累能力”。
2. **过程不可核对**：成果没有引用来源；看不到模型实际用了哪些材料、token 和成本；两次运行无法比较；失败只在流式里出现，刷新即丢。
3. **日常摩擦**：Task/Project 没有服务端搜索；没有 Prompt 模板，成功执行不能沉淀为 Skill；对话不能清空/重开；取消执行前端无入口。
4. **工程债**：解析阻塞事件循环、日志无脱敏、测试不覆盖 Postgres 迁移、Chat 工具调用靠关键词和开关、前端组件过大且无单测。

### 3.2 采用的手段

**复用（核心）**

- Artifact 全局列表与独立详情（筛选、标题搜索、版本、来源）。
- Task 持久引用 Artifact 作为上下文，**钉版本**；Chat 与 Execution 都可用。
- 成果编辑生成新版本（append-only），可切换当前版本。
- 从成果派生新 Task；Project 导出（后置）。

**可信**

- 运行卡：模型/参数、token 与成本、材料清单、步骤、产出、错误。
- 上下文查看器：只展示清单与统计，不展示全文/Prompt。
- 版本/运行 Diff，支持结果比较。
- 失败留痕、取消与重跑入口。
- Citation 试点（后置）。

**效率**

- ⌘K 全局搜索（Project/Task/File/Artifact/Message）。
- Task/Project 服务端搜索与分页，去掉 200 条静默截断。
- Prompt 模板与“保存为 Skill”。
- 对话上下文管理（清空/从某条重开，不引入多 Conversation）。

**工程硬化（已作为 M0 完成）**

- 文件读取/解析移入线程池，可配置超时，超时显式失败。
- 统一日志与 request-id，Key/Token 脱敏。
- Postgres 集成测试（迁移、外键、约束、downgrade）。
- Chat 改为「对话 / 工作」模式：对话无工具；工作模式由模型自行决定是否调用 4 个受控工具；不做关键词猜测，不自动保存成果。
- 并发/超时/预算/模型窗口配置化；前端引入 vitest 并拆分 composable。

### 3.3 范围与优先级

| 优先级 | 内容 |
|---|---|
| P0 | 工程硬化；全局 Artifacts；Task 引用成果；编辑/版本/当前版本 |
| P1 | 从成果派生 Task；运行卡；上下文查看器；Diff；失败留痕/取消/重跑；⌘K；搜索分页；模板；对话上下文管理 |
| P2 | Project 导出；Citation 试点 |

原则：先完成 P0 的复用闭环，再补可信与效率；P2 时间允许再做。

### 3.4 结果与验收

| 里程碑 | 结果 |
|---|---|
| **M0 工程硬化（已完成）** | 大文件解析不阻塞 API/SSE；日志可定位且不泄漏 Key；SQLite 128 / Postgres 59 / 前端 88 测试通过；工作模式可保存 Markdown 成果；任务删除可级联清理关联数据并返回明确错误。 |
| **M1 复用（下一步）** | Project A 的成果可引用进 Project B 的 Task；Chat/Execution 实际使用该成果；快照与 manifest 记录版本；被引用成果删除返回 409；全局 Artifacts 可找回；成果可编辑并生成新版本。 |
| **M2 可信** | 任一 Execution 可打开运行卡核对模型/参数/成本/材料/步骤/产出/错误；上下文清单可见；两个版本或两次运行可 Diff；失败可重试、运行可取消。 |
| **M3 效率** | ⌘K 能搜到并跳转五类实体；Task/Project 不再静默截断；模板可创建 Task；对话上下文可清空/重开。 |
| **v0.3.0 验收** | 用真实资料完成“跨 Project 引用 → 执行 → 复制/编辑成果 → 新建 Task”一条链；升级零丢失、迁移可回滚；测试与 E2E 通过。 |

### 3.5 关键规则

- **引用钉版本**：新版本不自动扩散；“更新到最新”是显式操作。
- **成果编辑 append-only**：保存创建新版本，旧版本不变；当前版本只移动指针。
- **引用冲突显式**：被引用成果删除返回 409；被其他 Task 引用的成果阻止删除并说明原因，不静默丢数据。
- **manifest 不存全文**：只存 kind/id/name/tokens/usage_mode。
- **Chat 模式无工具，工作模式模型决定工具**：不自动保存成果；失败不伪装成功，取消 ≠ 失败。
- **无新基础设施**：不引入向量库、消息队列、多 Agent、多用户。

### 3.6 非目标与边界

RAG/向量库/embedding；Office/OCR/音视频；MCP/GitHub/IDE/外部 Agent；多用户/协作/云同步/移动端；多 Agent/Workflow/能力市场；多 Conversation；PDF/Office 导出。  
触发条件（如资料规模、格式受阻频率）满足后再讨论，不在本阶段做。
